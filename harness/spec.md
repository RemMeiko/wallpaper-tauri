# 需求规格: Wallpaper-Tauri 第二轮开发

## 概述

这是 Wallpaper-Tauri 壁纸管理工具的第二轮迭代开发。第一轮已完成核心功能（Tab 布局、搜索多页加载、本地壁纸库、设为桌面壁纸、配置持久化、自动轮换），本轮聚焦于修复 3 个已知 Bug 并新增 2 个功能（壁纸收藏、以图搜图）。

目标用户是 Windows 桌面用户，希望通过一个本地应用方便地搜索、管理和切换桌面壁纸。

本轮优先级：Bug 修复优先于新功能开发。

## 核心功能

### Bug 修复

1. **搜索结果跨页去重**
   - 用户场景: 作为用户，我搜索壁纸并点击"加载更多"时，不应看到重复的壁纸
   - 根因: `search_wallpapers` 命令使用 `sorting=random`，导致 Wallhaven API 每次请求的随机排序不一致，跨页出现重复
   - 验收标准:
     - 用户搜索关键词后，点击"加载更多"3 次，所有结果中无重复壁纸（同一 id 不出现两次）
     - 搜索结果按稳定顺序排列（如按日期或相关度），多次加载更多后顺序一致
     - 修改排序方式后，搜索功能正常工作，返回结果数量与之前相当
     - 首次搜索仍能返回多样化的结果（不会因为固定排序导致每次搜索结果完全相同）

2. **设置页 Input 保存防抖优化**
   - 用户场景: 作为用户，我在设置页输入路径时，不应每按一个键就触发保存和 toast 提示
   - 根因: `SettingsTab.tsx` 中 Input 的 `onChange` 直接调用 `saveSettings`，每次按键都触发磁盘写入和 toast
   - 验收标准:
     - 用户在下载目录输入框中连续输入 10 个字符，只触发一次保存（停止输入后约 500-800ms 触发）
     - 用户在本地壁纸目录输入框中连续输入，同样只在停止输入后触发一次保存
     - 用户在轮换间隔输入框中连续修改数字，同样只在停止输入后触发一次保存
     - 防抖期间如果用户切换 Tab 或关闭应用，最后一次输入的值不会丢失（组件卸载时 flush）
     - 通过文件夹选择按钮选择目录时，仍然立即保存（不受防抖影响）
     - 轮换模式 Select 下拉选择仍然立即保存（不受防抖影响）
     - 保存成功后仍显示 toast 提示，但不会出现连续多个 toast 弹出

3. **本地壁纸库缩略图无法显示**
   - 用户场景: 作为用户，我打开本地壁纸 Tab 并选择目录后，应能看到壁纸缩略图
   - 根因: 使用 `convertFileSrc` 转换为 `asset://` 协议，但 Tauri v2 的 asset protocol 需要在 capabilities 中配置权限和 scope
   - 当前 capabilities (`src-tauri/capabilities/default.json`) 只有 `core:default`、`dialog:default`、`fs:default`，缺少 asset protocol 相关权限
   - 验收标准:
     - 用户选择一个包含 jpg/png 图片的本地目录后，所有图片缩略图正常显示
     - 图片加载过程中显示 skeleton 占位，加载完成后平滑过渡显示
     - 包含 20+ 张图片的目录，所有图片都能正常显示（不是只有部分能显示）
     - 路径中包含中文字符的图片也能正常显示
     - 路径中包含空格的图片也能正常显示

### 新功能

4. **壁纸收藏**
   - 用户场景: 作为用户，我可以收藏喜欢的壁纸（无论来自搜索结果还是本地库），并在专门的收藏页查看和管理
   - 验收标准:
     - **正常路径**:
       - 搜索结果的壁纸卡片上显示心形图标，点击后图标变为实心/高亮状态，表示已收藏
       - 本地壁纸卡片上同样显示心形图标，点击可收藏
       - Tab 栏新增"收藏"Tab，点击进入收藏列表页
       - 收藏页展示所有已收藏壁纸，以网格形式显示缩略图
       - 收藏页中每张壁纸可以取消收藏（点击心形图标或提供取消按钮）
       - 收藏页中每张壁纸可以"设为壁纸"（搜索来源的需先下载，本地来源的直接设置）
       - 已收藏的壁纸在搜索结果和本地库中显示已收藏状态（实心心形）
     - **边界情况**:
       - 收藏列表为空时，显示空状态提示（如"还没有收藏的壁纸"），不是空白页面
       - 收藏 50+ 张壁纸后，收藏页可正常滚动浏览
       - 同一张壁纸不能重复收藏（已收藏的再次点击为取消收藏）
     - **错误状态**:
       - 收藏数据文件 (`~/.wallpaper_app/favorites.json`) 不存在时，自动创建空列表
       - 收藏数据文件损坏时，提示用户并重置为空列表
     - **交互体验**:
       - 点击心形图标时有即时视觉反馈（不需要等待磁盘写入完成）
       - 收藏/取消收藏操作显示简短 toast 提示
       - 心形图标不影响卡片的点击选中行为（图标区域独立响应）

   > **假设**: 搜索来源的壁纸收藏时存储 URL + 元数据（id、resolution、category、path、thumb），本地来源的存储本地文件路径 + filename。两种来源通过一个 type 字段区分。
   > **假设**: 收藏页中搜索来源的壁纸显示网络缩略图（thumb URL），本地来源的显示本地文件缩略图（asset protocol）。
   > **假设**: 收藏页"设为壁纸"对搜索来源壁纸的行为是：先下载到下载目录，再设为壁纸（复用现有下载逻辑）。

5. **以图搜图（颜色搜索）**
   - 用户场景: 作为用户，我可以选择一张本地图片，应用提取其主色调后去 Wallhaven 搜索相似颜色的壁纸
   - 验收标准:
     - **正常路径**:
       - 搜索页新增"以图搜图"按钮（带图标），位于搜索栏附近
       - 点击按钮后打开系统文件选择对话框，可选择 jpg/png/bmp/webp 图片
       - 选择图片后，应用提取主色调并自动发起搜索
       - 搜索结果以与普通搜索相同的网格形式展示
       - 搜索结果支持"加载更多"分页
     - **边界情况**:
       - 用户取消文件选择对话框时，不触发任何操作，不显示错误
       - 选择非图片文件时，显示友好错误提示
       - 极小图片（如 1x1 像素）也能提取颜色并搜索，不崩溃
     - **错误状态**:
       - 颜色提取失败时，显示 toast 错误提示，不影响后续操作
       - 网络请求失败时，显示与普通搜索一致的错误提示
     - **交互体验**:
       - 选择图片后显示"正在分析颜色..."的加载状态
       - 颜色提取完成后自动切换到搜索状态，显示"搜索中..."
       - 搜索完成后，在搜索栏附近显示当前搜索的颜色色块（让用户知道搜的是什么颜色）

   > **假设**: 使用 Wallhaven API 的 `colors` 参数（格式为 hex 颜色值如 `660000`）进行颜色搜索。
   > **假设**: 后端新增 `extract_image_colors` Tauri 命令，使用 Rust `image` crate 读取图片并计算主色调（取图片像素的平均色或最频繁色），返回一个 hex 颜色字符串。
   > **假设**: 以图搜图的结果复用现有搜索结果的展示逻辑（WallpaperGrid），支持选中、下载、设为壁纸等所有现有操作。

## 技术架构

- 语言/框架: Tauri v2 + React 18 + TypeScript + Tailwind CSS v4 + shadcn/ui，后端 Rust
- 关键模式:
  - 前端状态管理使用 React hooks（useState/useCallback/useMemo）
  - 后端通过 Tauri commands 暴露功能，前端通过 `invoke` 调用
  - 数据持久化使用本地 JSON 文件（`~/.wallpaper_app/` 目录）
  - 图片显示使用 Tauri asset protocol（`convertFileSrc`）
- 新增依赖:
  - Rust: `image` crate（用于以图搜图的颜色提取）
  - 前端: 无新增依赖（防抖可手写或用现有工具）

## 不在范围内

- 壁纸标签/分组管理（仅做收藏，不做分类）
- 批量收藏/批量取消收藏
- 收藏数据云同步
- 以图搜图的高级算法（如特征向量匹配），仅用颜色近似
- 多显示器独立壁纸设置
- 系统托盘/开机自启
- macOS/Linux 支持

## 风险和约束

1. **Tauri v2 asset protocol 配置**: 本地缩略图 Bug 的根因可能涉及 capabilities 配置、CSP 策略、或路径格式问题，需要逐一排查。当前 `capabilities/default.json` 缺少 asset protocol scope 配置是最可能的原因。
2. **Wallhaven API 颜色搜索精度**: `colors` 参数只支持单个颜色值，搜索结果可能与用户预期有偏差，这是 API 限制。
3. **image crate 体积**: 添加 `image` crate 会增加编译产物体积，但对桌面应用影响可接受。
4. **收藏数据一致性**: 本地壁纸被删除后，收藏列表中对应项的缩略图将无法显示，需要优雅处理（显示占位图或标记为"文件已移除"）。
5. **防抖实现**: 需要处理组件卸载时的 flush 逻辑，避免用户最后一次输入丢失。
